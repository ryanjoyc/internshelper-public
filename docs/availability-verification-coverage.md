## Maintenance rules

- Add a corpus case for each newly discovered production availability failure before fixing that failure.
- Obtain the user's approval before changing an expected user-visible outcome or locked product expectation.
- Engineers may refactor fixtures and add cases that follow already-approved policy without a separate product decision.
- Keep real-derived fixtures minimal and sanitized; retain only excerpts needed to reproduce the behavior.
- Increment schema_version for incompatible manifest-shape changes and policy_version for approved expectation changes.

## Commands

```bash
# Offline integrity, generated-doc, fake-component, and mutant checks (default-running)
.venv/bin/python -m pytest tests/test_availability_corpus.py

# Approved production contract; all 109 layer expectations must pass
.venv/bin/python -m pytest -q -m availability_contract

# Optional, read-only, informational network probes
.venv/bin/python -m pytest -q -m live_canary -s
```

The default suite excludes `availability_contract`, `live_canary`, and `browser`. The
canaries report observed HTTP results but never assert that a posting remains live.

name: principle-experience-first
description: Apply when product, UI, API, or feature-scope decisions trade implementation convenience against the experience of the person using or maintaining the result.
---

# Experience first

- Protect the core user workflow before adding options.
- Prefer fewer polished behaviors to more rough ones.
- Prototype uncertain interactions before hardening production code.
- Treat alignment, focus, feedback, errors, loading, and recovery as product behavior.
- Remove features or controls that do not earn their complexity.
- Count the next maintainer and API consumer as users too.

Implementation convenience is a valid cost, but it does not define the target experience.
